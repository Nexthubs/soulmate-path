## 1. Scope completed
- **`WheelDatePicker.tsx` rewritten around a local full-date draft (§8 item 1):** column scrolls/taps update only the internal draft (the SELECTED pill reflects it instantly); the parent receives **exactly one `onChange` per settle** — when the LAST moving column stabilizes — never per row. The `YYYY-MM-DD` submitAnswer contract, zodiac derivation (SP-204) and restore flow are unchanged.
- **Settlement (§8 items 2–3):** `scrollend` (Chromium 114+, bound natively — React has no synthetic event) is the verified end signal; a 120ms no-new-scroll-event fallback covers other browsers. Settling checks the FINAL position and auto-snaps exactly before reporting stability; snap/RAF is never treated as settled by itself.
- **Moving gating (§8 item 5):** new `onMovingChange` aggregates the three columns' moving states (`data-moving` attribute on the root for observability); `quiz/page.tsx` disables Next while any column moves and re-enables on settle, when the settled draft is committed. Date submit keeps its existing contract and handlers.
- **Programmatic vs gesture separation (§8 item 4):** mount/restore/clamp repositioning scrolls DIRECTLY (no glide) with its instant events flagged; user far-row taps glide smoothly with **position-tracked** suppression — the tapped row's exact `scrollTop` target is stored, every event before arrival is a passing row and can never update the draft or the committed value; arrival clears the flag and settles at the target.
- **Clamping (§8 item 6):** exported pure `clampYMD` (year range, month 0–11, day ≤ days-in-month with leap-year rules) applied to every draft transition; February/30-31 lists adapt live; external `value` changes (Back/restore) ALWAYS override the draft; an empty/invalid stored value preserves the mount-sync contract (default emitted once so Next is never stuck).
- **Cleanup (§8 item 7):** settle timers cleared on unmount, on `disabled`, and on the external-reset signal; in-flight glide targets dropped on the same signals so a restored value is never overwritten by stale settle work.
- **Visuals untouched (§8 item 9):** white card, center band, edge fades, snap scrolling, and the stable year/month arrays are unchanged; no virtualization added.
- **Baseline correction:** `docs/UI-BATCH0-BASELINE.md` §5.1/§9 updated — the batch-0 "wheel already isolated" conclusion is identified as an instrumentation artifact (the label loop overwrote QuizPageContent's fiber label with `wheel-internal:*` on the wheel page) and the pre-batch-4 implementation is correctly described as per-row `onChange` driving parent re-renders.

## 8. Deviations / implementation decisions
- **Two defects were found and fixed during browser verification (the value of real-interaction testing):**
  1. First tap-glide implementation dropped the immediate draft update — the tapped value was lost when the glide's settle only checked position. Fixed by setting the draft to the tapped row up front and committing on arrival.
  2. The initial 600ms fixed programmatic window was shorter than long glides (29-row year glide): the glide tail was misread as user scrolling and the 120ms fallback settle snapped MID-GLIDE onto a passing row (submitted value April 21, 2014 instead of April 27, 2024 — caught by screenshot). Fixed by replacing the time window with **position-tracked glide targets**: events before the exact target position are ignored regardless of timing; the no-scrollend fallback window was extended to 3s as a bounded safety net.
- The settle-time fallback (120ms) applies only to user scrolling on browsers without `scrollend`; `scrollend` is bound natively because React has no synthetic event for it.
- `data-moving` on the picker root is an observability attribute for tests/probes, not styling state.

## 8.1 Audit remediation (Codex review of the uncommitted wave, 2026-09-30)

4. **P2 — clamped display date diverged from the submitted date (Fixed):** an externally restored value that is valid but outside the wheel's year range (e.g. `1900-02-28` with minYear 1926) now syncs the clamped date back to the parent, so the displayed and submitted values are identical. The reconcile logic is extracted as the exported pure `reconcileExternalValue(value, minYear, maxYear)` (`{ draft, emitValue }`: emits when the value is unparseable/empty OR clamping changed it) and covered by 5 new unit tests, including the out-of-range-year case the audit requested and leap-day in-range/out-of-range variants. The mount-sync contract (empty/invalid value emits the default so Next is never stuck) is preserved by the same function.
