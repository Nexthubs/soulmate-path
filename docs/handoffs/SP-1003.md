First owner attempt accidentally resent CANCELLED/ACTIVATED instead of the sale event; detected via log event-id analysis and corrected — the misfires themselves produced valid extra dedupe evidence.
- One nuance recorded: for same-event-id replays, the **event-id dedupe layer** (not the terminal-state guard) is what neutralizes stale ACTIVATED deliveries. The terminal-immutability guard for a *different* event id claiming ACTIVATED after CANCELLED remains unit-covered only; a live probe of that would need a crafted/second event and is left to owner discretion (it would effectively require PayPal to mint a new ACTIVATED event for a cancelled subscription, which sandbox does not produce naturally).
