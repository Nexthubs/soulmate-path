## 8. Deviations / implementation decisions
- **Fixture mode became opt-in** (`?fixture=true`) — SP-107 rendered every dev session as a fixture, which would have made the live page unreachable in development; production behavior unchanged.
- **Public URL preferred over presigned:** the user's R2 deployment exposes a public custom-domain prefix (`r2-morii.zhaozhao.org`), giving stable cacheable URLs; presigned 1h URLs remain the fallback for private-bucket deployments (both verified live).
- **`.env` anchored to repo root:** the CWD-relative load silently produced an unconfigured provider/storage when uvicorn ran from `backend/` (real occurrence during this task's dev-server run; the lifespan worker then terminally failed two stale leftover jobs). Root-anchored resolution keeps one config file and removes the startup-directory hazard. Tests MUST run with any live `uvicorn` stopped: a running server's lifespan workers poll the shared dev DB and race test-enqueued jobs (observed once; suite green after stop).
- **Failed-state Retry reuses the generate endpoint** rather than a dedicated support flow: server policy (SP-604) is the single retry authority; the UI cannot force a second generation.

## 9. New risks / TBDs / known limitations
- The `r2-morii.zhaozhao.org` public prefix makes stored sketches publicly readable to anyone with the URL (unguessable UUID-v4 artifact keys). If product requires access control on assets, switch to presigned-only (remove the prefix) or add a signed-proxy endpoint — RECOVERY-01/§20-adjacent, flag for M4/M6 review.
- Stale queued jobs from pre-SP-604 test runs were drained by the dev server's workers as FAILED_PERMANENT (expected; no artifact rows affected beyond their own test sessions).
- `next/image` renders the CDN URL with `unoptimized` (existing SP-107 choice) — no image optimizer dependency on the R2 domain.
