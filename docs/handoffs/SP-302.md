## 8. Deviations / implementation decisions
- **M-1 Audit Remediation (Sample Data Rationale):** Default sample values (`"female"`, `"30-40"`, `"Latino"`) in both backend `build_sample_email_summary()` and frontend `EmailCaptureView` are intentionally chosen to match the canonical Figma design preview (nodes 102:490 & 102:562). When applied, `is_sample_data: true` is always flagged and prominently communicated via the UI badge (`Demo Preview (No Quiz Answers Submitted)`) and explanatory subtitle, ensuring users never confuse sample fixture data with their own answers.
- **M-3 Audit Remediation (Profile vs. Answers Fallback Strategy):** In `backend/app/soulmate/services/summary_service.py`, `SummaryService` uses a resilient two-tier data resolution strategy:
  1. Primary: Reads normalized fields from `SoulmateProfile` if the profile record has been materialized.
  2. Fallback: If `SoulmateProfile` has not yet been materialized (e.g. answers saved but flow not finalized), reads directly from `SoulmateAnswer` (`q02`, `q03`, `q05`, `q06`).
  3. Default: Returns sample preview summary (`is_sample_data=True`).
  This fallback prevents blank badges or 500 errors during transition. In WAVE 5 (Result page & Entitlement), the end-to-end profile materialization lifecycle will be confirmed.
- Preserved client-side fixture fallback in `frontend/src/app/soulmate/email/page.tsx` so that local offline dev or disconnected fixture mode continues to function cleanly if backend is unreachable.
