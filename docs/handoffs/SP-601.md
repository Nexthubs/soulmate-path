## 1. Scope completed
- **Versioned prompt template file** (`config/prompts/soulmate-sketch/v1.txt`):
  - Migrated the PRD "Soulmate Pencil Portrait Prompt" verbatim (all sections: Required Attributes, Character Requirements, Portrait Composition, Pencil Sketch Style, Aesthetic Direction, Background, Priority Order) as the `prompt_name=soulmate_pencil_portrait`, `prompt_version=v1` template (DEV-SPEC §11.3).
  - Placeholder delimiters normalized from PRD table-cell `{{...}}` to the §12-mandated single-brace `{gender}` / `{age_range}` / `{ethnicity}` / `{features}` (see §8 Deviations).
- **Sketch prompt registry / loader / renderer** (`backend/app/soulmate/domain/sketch_prompt.py`):
  - `load_sketch_prompt_template(version=None)` — loads and caches versioned templates from `config/prompts/soulmate-sketch/<version>.txt`; default version is config-driven (`SOULMATE_SKETCH_PROMPT_VERSION`, default `v1`); path-traversal-safe version check.
  - `SketchPromptTemplate` (frozen pydantic model) — validates on construction: no PRD-style `{{...}}` delimiters, placeholders ⊆ §12 whitelist, all four §12 variables present, no stray braces outside placeholders; exposes `sha256` (§12 "Prompt version hash").
  - `SketchPromptInputs` (extra="forbid") — exactly the four §12 variables; strips values; rejects empty/whitespace values and brace characters.
  - `map_sketch_option_to_readable()` + `SKETCH_INPUT_OPTION_LABELS` — explicit option-code → human-readable mapping for q03/q05/q06/q07 (§12 "option code → 人类可读值映射"); unknown codes raise, raw codes never forwarded to a provider.
  - `validate_sketch_input_mapping_coverage()` — drift guard: mapping table must cover exactly the options defined in the canonical quiz config for q03/q05/q06/q07; runs inside every input build.
  - `build_sketch_prompt_inputs(profile)` — `SoulmateProfileV1.to_sketch_input()` (SP-205) → explicit inputs; gender strictly from `preferred_partner_gender` (Q03, QUIZ-01); `features` strictly from `key_soulmate_quality` (Q07) unchanged (PROMPT-01 OPEN — no reinterpretation).
  - `render_sketch_prompt()` — substitutes variables, then rejects any residual `{`/`}` in the rendered text; format failures (only reachable via validation-bypassing templates) are wrapped as `SketchPromptTemplateError`. Client-submitted prompt text is structurally impossible: the only entry point accepts profile-derived inputs against a server-owned template (§12 "禁止客户端提交任意 prompt").
  - `build_rendered_sketch_prompt(profile)` — one-call entry for the generation path.
  - `RenderedSketchPrompt` — carries `prompt_name` / `prompt_version` / `template_sha256` / `model` (from `SOULMATE_IMAGE_MODEL`, default `gpt-image-2` per §11.3) / `inputs` / `rendered_text`; `artifact_column_values()` returns exactly the persistable `SoulmateArtifact` columns (`prompt_version`, `model`, `input_json`).
- **Domain exports** (`backend/app/soulmate/domain/__init__.py`): exported the above public API for SP-602/603 consumption.

## 8. Deviations / implementation decisions
- **Placeholder delimiters:** PRD source uses `{{gender}}` (markdown-table escaped); DEV-SPEC §12 lists the allowed variables as `{gender}` etc. Followed the spec syntax (single braces) and migrated PRD text otherwise verbatim; template validation additionally rejects `{{...}}` so future editors cannot regress. Recorded here because §0.1 does not yet list this source-material difference.
- **Human-readable mapping values** are an explicit in-code table (emoji-free quiz labels, e.g. `asian` → `Asian`, `age_30_40` → `30-40`) matching the §11.2 example, instead of runtime emoji-stripping of UI labels — deterministic provider-bound text, guarded against config drift by `validate_sketch_input_mapping_coverage()`.
- **Mapping coverage check runs inside `build_sketch_prompt_inputs`** so a future quiz-config change fails loudly at first generation attempt rather than silently forwarding an unmapped raw code.

## 9. New risks / TBDs / known limitations
- `q06=no_preference` maps to the literal text "No preference" in an ethnicity slot the PRD prompt treats as a hard visual constraint. DEV-SPEC/PROMPT-01 do not address this option; no product decision taken here. Flag for product alongside PROMPT-01 resolution (affected prompt quality only).
- `soulmate_artifacts` has no columns for `prompt_name` or template hash; if §11.3 "model snapshot (若使用)" evidence is later required on the artifact itself, a migration decision will be needed (not required by current task acceptance).
