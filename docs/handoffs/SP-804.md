## 2026-09-27 Wave 8 audit remediation — current checkpoint

- **Fixes applied (audit H-3 + M-2):**
  - **H-3:** the "no refund is issued for the current cycle" assertion was REMOVED from the cancel confirmation — §9.8 does not authorize a blanket no-refund statement. The dialog now makes no refund claim of any kind; refund policy/wording is tracked as OPEN decision `REFUND-01` in `DECISIONS.md` and requires owner approval before any refund statement ships.
  - **H-2:** the dialog quotes a renewal price only when it is a **verified PayPal plan snapshot** (`price_verified` from the backend; gating via `resolveQuotedCancelPrice`). Unverified prices render no amount at all. Verified by E2E: seeded unverified row → dialog without price; verified row → "Your plan renews at $29.00/month".
  - **M-2:** `CancelConfirmationDialog.paidThroughDisplay` is now nullable — when the paid-cycle end is unknown the dialog renders "Any remaining access after cancellation depends on your billing state and will be confirmed afterwards." instead of "keep access until N/A". Backend `cancel_subscription` success message is now state-aware (paid + known `paid_through_at` → billing-cycle access; paid + unknown date → end date to be confirmed; unpaid → "No further charges will occur.").
- **Acceptance gap (unchanged, owner-scheduled):** the real PayPal Sandbox success-path E2E through the new dialog remains NOT_RUN — it requires creating a fresh real sandbox subscription via interactive PayPal approval (no sandbox buyer credentials/session available here; the M3-gate subscription was already cancelled). Runbook: complete quiz→email→subscribe with sandbox buyer → approve PayPal popup → confirm → open `/soulmate/settings` → Cancel → Confirm → expect 200 CANCELLED + paid-through display + retention notice.
