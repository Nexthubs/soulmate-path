## 1. Scope completed
- **Event ID Idempotency & Persistence:**
  - Persisted `PayPalWebhookEvent` with `event_id` within an atomic database transaction.
  - Deduped incoming webhooks: if `event_id` is already stored in `paypal_webhook_events`, subsequent processing calls return immediately without executing any business logic (`status="DUPLICATE"`).
  - Enforced secondary idempotency check at the `SubscriptionPayment` ledger level via `provider_payment_id` deduplication (handles edge cases where provider retries with different event IDs).
- **Out-of-Order & Monotonic State Transitions:**
  - Tolerates webhook events arriving out of chronological order.
  - Enforced terminal state immutability: once a subscription transitions to `CANCELLED` or `EXPIRED`, stale or out-of-order `BILLING.SUBSCRIPTION.ACTIVATED` / `BILLING.SUBSCRIPTION.SUSPENDED` events are ignored and cannot reactivate the subscription.
  - Enforced timestamp monotonicity checks: `ACTIVATED` events with timestamps prior to or equal to recorded `cancelled_at` or `suspended_at` are safely ignored.
  - Handled in-flight payments arriving after cancellation: recorded as `COMPLETED` in the `subscription_payments` ledger for financial auditability while strictly preserving `CANCELLED` status on the subscription without reactivating it.
  - Handled payment failure (`BILLING.SUBSCRIPTION.PAYMENT.FAILED`): recorded in the ledger with `FAILED` status without deleting or regressing previously granted entitlements (`subscription_success_at` and generated artifacts remain intact).
  - Protected artifact initialization: ensured `_ensure_artifacts_initialized` adheres strictly to `uq_soulmate_one_sketch_per_email` and `uq_soulmate_artifacts_session_type_version` so duplicate or subsequent triggers never violate uniqueness.
- **Ambiguous State Reconciliation:**
  - Implemented `reconcile_subscription(provider_sub_id, db, client)`: fetches authoritative subscription details from PayPal REST API if local subscription record is absent or ambiguous.
  - Links discovered subscriptions to sessions via `custom_id` or normalized email.
  - Respects state monotonicity during reconciliation: PayPal API state will never overwrite an existing local terminal `CANCELLED` status.
