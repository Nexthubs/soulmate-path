## 8. Deviations / implementation decisions
- Interface method returns `ReportGenerationResult` instead of bare `SoulmateReportV1` (§13.3) — same accepted deviation as SP-602's sketch provider, needed to carry the §13.3/§14 tracing metadata that SP-702's save persists (`provider`/`model`/`prompt_version`/`provider_request_id`).
- Prompt templates use a Python-class validator (`ReportPromptTemplate`) instead of a pydantic model — small, frozen-snapshot semantics identical to `SketchPromptTemplate` without extra dependencies.
- `response_format={"type":"json_object"}` intentionally omitted from the chat payload for maximum OpenAI-compatible-gateway compatibility; JSON-only behavior is the template's responsibility, and malformed output fails closed regardless.
- Chat-completions (not the images API) is the integration point for the owner-directed text endpoint; `SOULMATE_REPORT_PROMPT_VERSION` config exists but the per-call `input.prompt_version` (§13.3) governs which template renders — SP-706 will wire the config default into the trigger.

## 9. New risks / TBDs / known limitations
