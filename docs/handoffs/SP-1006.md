## 7. Rollback / disable strategy (acceptance artifact)

Per-capability kill switches, all already implemented — no code changes required:

| Capability | Disable action | Effect after rollback |
|---|---|---|
| PayPal checkout (go-live rollback) | Revert `PAYPAL_ENV` to `sandbox` (or revoke production webhook) and redeploy | New subscriptions impossible; `validate_production_config` fails closed at startup, so pair with a config rollout that keeps the app serving already-subscribed users (existing entitlements/artifacts unaffected — reads never depend on provider reachability). |
| Report generation (production stays off by default) | Keep `SOULMATE_REPORT_PROVIDER` empty (REPORT-01 default) | `POST /artifacts/report/generate` fails closed 503; already-completed reports remain readable (retention promise §9.8). Enable only on owner order after prompt QA. |
| Generation workers | `JOB_WORKER_ENABLED=false` | Queues drain-stopped; in-flight jobs finish; no new provider calls. Sketch/report triggers enqueue nothing while off. |
| Sketch pipeline (provider outage) | Env: remove/blank OpenAI-compatible gateway key → jobs fail retryable, artifacts stay LOCKED/FAILED; bounded retry cap holds | No partial charges: sketch is entitlement-gated, not per-purchase. |
| Asset exposure (worst case) | Empty `OBJECT_STORAGE_PUBLIC_URL_PREFIX` is already mandatory; rotate R2 keys to revoke all presigned URLs immediately | Artifacts unreadable until re-issued keys; no public exposure path exists. |
| Analytics | ANALYTICS-01 default: no provider sink in production until owner decision — events remain in structured logs only | No third-party data flow to disable; adding a sink later is config-only by design (§18 transport abstraction). |
| Marketing content | LEGAL-01/§21 gate: launch with testimonials/statistics removed or replaced with clearly-labeled non-user statements | No fake social proof can ship; CMS items are the only source. |

Data-loss posture: entitlement/ledger state is server-persisted and idempotent (SP-406/1003 replay matrix); rollback of any frontend/backend deploy does not destroy paid artifacts (durable R2 objects keyed by §11.7 keys).
