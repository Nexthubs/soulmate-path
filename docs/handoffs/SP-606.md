## 1. Scope completed
- **Canonical identity key documented and enforced in code:** `email_normalized` is the DB-level sketch identity (per the task Note: `user_id` is deterministically derived from the normalized email in SP-301/§8.3 but is never set on anonymous sessions, so email-keying preserves the linked-user identity without a migration). `uq_soulmate_one_sketch_per_email` (partial unique index, SP-501/§11.5/§14) is the DB backstop — now proven directly by test.
- **Identity-level generation convergence** (`SketchGenerationService.enqueue_sketch_generation`, `backend/app/soulmate/services/sketch_generation_service.py`) implementing §11.5 exactly:
  - resolution is identity-wide (`_resolve_identity_sketch_artifact`: own session's row OR the email-owned row; the unique index guarantees at most one SKETCH row per email);
  - identity asset COMPLETED → returned as-is, **the model is never called**, no new job;
  - any existing identity job (QUEUED/PROCESSING/terminal) → converged on — **never a second job** (this replaces SP-603's fall-through-and-INSERT-converge path with a single explicit converge branch; net behavior identical, one less failure-mode path);
  - no job yet → exactly one is created; TIME-01 gates on the **asset's persisted `unlock_at`** regardless of which entitled session triggers, so a second session can drive the identity's single generation without ever bypassing the server-side unlock;
  - outcome carries `cross_session=True` + `job=None` when the resolved artifact belongs to a different session — **read isolation preserved per Decision RECOVERY-01** ("Do NOT restore bare-email cross-session reads"): reads/status stay session-scoped, and the generate endpoint's response for a non-owning session never exposes the owning session's job/artifact state (verified at API level).
- **Decision record:** RECOVERY-01 entry updated (2026-09-26 SP-606 line) — write-path identity semantics shipped; the recovery-display product choice (options a/b/c) remains OPEN.
- **Test helper:** `seed_generation_session(with_sketch=…, display_email=…)` to model second-session identities and normalization cases.

## 7. High-risk checks when applicable
- **Cross-user data exposure (§20):** the non-owning session's response is derived solely from its own session-scoped rows; `job=None` for cross-session outcomes; asserted at the API level (`sketch.unlock_at is None`, `status == "LOCKED"`, `job_status is None`).
- **TIME-01:** the unlock gate uses the asset's persisted `unlock_at` against the server clock — a second session cannot trigger generation earlier than the asset's own unlock.
- **Duplicate assets:** four layers unchanged (identity convergence, completion short-circuit, phase-C guards, partial unique index) plus the new direct DB-constraint test.
- **Payment/entitlement:** the trigger still requires PAY-AUTH-01 entitlement on the triggering session.

## 8. Deviations / implementation decisions
- **Cross-session trigger allowed (write-side):** §11.5 rules are identity-level, so any entitled session of the identity may create/converge the single job — this also resolves the "politeness deadlock" where whichever session self-heals first owns the row and only the row owner could drive generation. Reads stay session-scoped (RECOVERY-01 precedence over a literal identity-wide read of §11.5).
- **Test claim scoping fix:** `test_worker_missing_profile_fails_permanent` was still calling the worker without `job_id` scoping (missed by the SP-604 bulk edit) and intermittently claimed a stale QUEUED job left in the shared dev DB (its artifact already COMPLETED → short-circuit returned COMPLETED). Scoping added; all worker calls in queue tests are now explicitly scoped.
- **SP-501 ensure commit semantics surfaced:** ensure only flushes; callers own the commit (documented via a test comment where raw sessions drive it).

## 9. New risks / TBDs / known limitations
- Until RECOVERY-01 resolves, a second-session user sees LOCKED-with-no-unlock on their Result page even though the identity owns a sketch — intentional per the decision; support/refund fallbacks apply (see decision's reachability boundary).
- Identity resolution assumes the partial unique index invariant (≤1 SKETCH row per email); if a future migration relaxes it, `_resolve_identity_sketch_artifact` must gain explicit ownership ordering.
