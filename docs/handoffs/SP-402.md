## 1. Scope completed
- **PayPal Subscription UI Component (`frontend/src/soulmate/components/subscribe/PayPalSubscriptionButton.tsx`):**
  - Integrated official `@paypal/paypal-js` SDK loader with `vault: true`, `intent: "subscription"`, and dynamic `currency`.
  - Implemented `createSubscription` callback invoking `actions.subscription.create({ plan_id: planId })` targeting server-selected billing plan.
  - Implemented `onApprove` callback capturing `data.subscriptionID` and invoking parent handler without mutating entitlement.
  - Implemented `onCancel` and `onError` callbacks for graceful failure/cancellation handling.
  - Added deterministic test helpers (`data-testid="mock-paypal-approve-btn"`, etc.) strictly isolated to `process.env.NODE_ENV === "test"`.
  - Handled loading spinner and script loading failure with retry action.
- **Subscribe Page Integration (`frontend/src/app/soulmate/subscribe/page.tsx`):**
  - Bound `PayPalSubscriptionButton` to dynamic server offer (`getSubscriptionOffer(sessionId)`).
  - Enforced Decision `PAY-01`: Prices and disclosures (`today_text`, `renewal_text`, `terms_text`) dynamically rendered from server offer, never hardcoded on client.
  - Enforced Decision `PAY-02`: When `offer.eligibility.is_blocked` is true, displays blocked banner and suppresses PayPal button.
  - Enforced Invariant `PAY-AUTH-01`: `handleApprove` extracts `subscriptionID`, preserves `session_id`, and navigates to `${SOULMATE_ROUTES.PAYMENT_PROCESSING}?subscription_id=...`; never writes to localStorage, cookies, or grants paid status.
  - Implemented recoverable state management: `paymentNotice` state renders dismissible `payment-cancel-notice` or `payment-error-notice` banners while keeping the checkout button fully active and retryable.
  - Preserved existing route guard checks (email required) and fixture mode previews.
- **Payment Processing Route (`frontend/src/app/soulmate/payment-processing/page.tsx`):**
  - Created App Router page matching DEV-SPEC §9.3 and §15.8.
  - Reads `subscription_id` and `session_id` query parameters.
  - Renders animated verification state and displays `processing-subscription-badge`.
  - Handles missing subscription ID gracefully with `return-subscribe-btn`.
  - Implements timed notice for longer confirmation durations (DEV-SPEC §15.8).
  - Explicitly documents and verifies that paid entitlement is not granted client-side (pending SP-403 / webhook reconciliation).
- **Automated Test Coverage:**
  - Added 14 unit and integration tests in `frontend/tests/paypal-subscription-checkout.test.tsx` verifying all acceptance criteria and invariant `PAY-AUTH-01`.
  - Added App Router page tests in `frontend/tests/app-pages.test.tsx` for `/soulmate/payment-processing`.
