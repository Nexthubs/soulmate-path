## 2026-09-27 Wave 8 audit remediation — current checkpoint

- **Fixes applied (audit H-1 + H-2):**
  - `GET /subscription/status?reconcile=true` now reconciles **paid** subscriptions too (the old gate skipped everything with `first_payment_at` set, so paid users always saw local-only records). Terminal `CANCELLED`/`EXPIRED` states stay skipped (monotonic, no refresh needed). Price verification (`verify_price=True`) rides along on this path.
  - Binding-time provider price verification: `confirm_paypal_subscription` fetches the bound PayPal plan (`get_plan`), extracts the last REGULAR billing cycle's fixed price, and stores it as the subscription's `currency`/`regular_price` with `price_verified_at` set. The hard-coded `Decimal("29.00")` fallback was removed (AGENTS.md §4 violation). Fail-open: if the plan fetch fails, the configured price is kept as **provisional** (`price_verified_at=None`) and neither provider nor config pricing available fails the binding closed.
  - New migration `0006_price_verification` (additive `subscriptions.price_verified_at`), applied to the shared dev DB (head). Status response adds `price_verified: bool`.
  - `reconcile_subscription` gained opt-in `verify_price` (default False so webhook-driven reconciliations add no plan fetch).

## 1. Scope completed
- **Backend (additive contract):** `SubscriptionStatusResponse` now carries `currency` and `regular_price` (decimal string), populated from the provider-reconciled subscription row (`sub.currency`, `sub.regular_price` — persisted from the server-configured offer at confirm time). `NONE` responses carry no price data. Single construction site changed; all `NONE` sites default to `None`.
- **Frontend API type:** `SubscriptionStatusResponse` gains optional `currency` / `regular_price`.
- **Settings card displays all acceptance data** (`SubscriptionSettingsAction`):
  - current plan row (`data-testid="subscription-plan-info"`): "Monthly" per the V1 single-plan billing model (DEV-SPEC §9.1), extended to "Monthly — {price}/month" when the backend provides a price;
  - status badge (existing: Active/Cancelled/Pending, unchanged);
  - regular monthly price formatted by the new pure helper `formatSubscriptionPrice` (Intl currency formatting from backend `currency`+`regular_price`; returns null for missing/invalid/non-positive prices so the UI never fabricates one);
  - next billing (active state, existing) or paid-through (cancelled state, existing).
- **Settings page** passes the new fields through and mounts the shared `DrawerMenuButton` in the page header — Figma `102:1423` places the drawer trigger on the settings page; this reuses the SP-801 global provider (no new navigation infrastructure).
- The page continues to load status with `?reconcile=true` (SP-408 authoritative PayPal reconciliation), satisfying "provider-reconciled backend state".
