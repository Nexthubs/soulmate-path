## 1. Scope completed
- **Result page wired to the live aggregate API (SP-503):** `/soulmate/result` now fetches `GET /api/soulmate/result` via the new `useResultAggregate` hook and renders sketch/report cards from server data. Dev fixture preview mode (`?fixture=true`, non-production) is preserved unchanged for QA.
- **Server-time offset calibration (TIME-01, AC 1):**
  - `calculateServerClockOffsetMs(server_time, clientNow)` computes the client-to-server offset at every fetch.
  - `getCalibratedRemainingSeconds(unlock_at, offset, clientNow)` anchors the countdown to server time via the offset. A client clock wrong by ±hours observes an identical countdown (unit-proven for ahead/behind/correct clocks).
  - `ResultItemCard` accepts `clockOffsetMs` (preferred) or falls back to its `serverTime` prop; the countdown is recomputed from absolute timestamps on every recalibration, so it is immune to tab-sleep drift (no per-second error accumulation).
- **Refresh recalibrates from the server (AC 2):** every successful `useResultAggregate` fetch (initial, manual `refresh`, zero-triggered refetch) recomputes `clockOffsetMs` from the fresh `server_time` and the cards re-derive remaining time from the new offset + persisted `unlock_at`.
- **Reaching zero triggers a refetch, never a local unlock (AC 3, TIME-01):**
  - `evaluateCountdownZeroNotification` (pure, unit-tested): when the calibrated countdown reaches 0 while the server still reports LOCKED, the card notifies the parent exactly once per `unlock_at`; a later refetch returning remaining time resets the one-shot guard.
  - The page passes `onCountdownZero` → `useResultAggregate.onCountdownZero` → refetch. The server response (`availability`/`status` from SP-502/SP-503, plus SP-501 self-heal) decides any unlock.
  - SSR/TIME-01 regression covered: a card calibrated past zero stays `data-ui-state="countdown"` with `data-availability="LOCKED"` and shows `00:00:00`.
- **Live-state UX:** production loading spinner (never renders fixture placeholder data); 403 → restricted view with subscribe CTA; other errors → retry view calling `refresh`.
- **Server combined status consumed:** `deriveCombinedUIState` prefers the server-returned per-artifact `status` (SP-502 §10.3 derivation) when present and falls back to the orthogonal availability×generation matrix for fixtures (backward compatible with SP-106).
- **API client:** `getResultAggregate` in `frontend/src/soulmate/api/result.ts` following the repo fetch pattern (`credentials: "include"`, `parseApiError`).

## 7. High-risk checks when applicable

- Extracted the zero-notification decision into a pure function (`evaluateCountdownZeroNotification`) so the once-per-unlock semantics are unit-testable in this repo's SSR-only test environment (no jsdom/testing-library).

## 9. New risks / TBDs / known limitations

- Local per-second ticking remains display interpolation between calibrations (existing SP-106 mechanism); long-tab-sleep drift self-corrects on the next refetch or recalibration.

## 13. Wave 5 audit addendum (2026-09-26)

- **H1 (git persistence):** frontend changes committed as `caa6fe9`; audit fixes in the follow-up `fix(wave5)` commit.
- **H4 (production window could render fixture data):** CONFIRMED and fixed. Root cause: `isLoading` was initialized from the first render's `enabled=false` (guard not yet resolved), so after the guard allowed, `isLoading` stayed false with no data and the page fell through to `SoulmateResultView`'s default fixture parameter. Fix: `SoulmateResultView` now REQUIRES `initialData` (no default fixture parameter); `page.tsx` computes `liveData` first and renders, in live mode: error view (403-aware) → production loading spinner → dev/test neutral fixture shell → live data. Production live mode can no longer render fixture placeholder data in any window.
- **H5 (refetch/polling did not update mounted cards):** CONFIRMED and fixed. Root cause: `useState(initialData)` copied the prop only at mount. Fix: view data is now derived (`previewOverride ?? initialData`) with no prop→state copy; dev/QA preview overrides are a separate state. Live evidence: with the real backend, flipping the DB artifact to COMPLETED updated the mounted card to "Your Portrait is Ready!" without any page reload.
- **H3 (browser polling behavior):** live local E2E executed 2026-09-26 (real backend on :8000 + Next dev on :3000 + signed session cookie + seeded entitled session): aggregate loaded as "[Live Server Data]"; sketch rendered GENERATING from server data; report countdown ticked in real time (23:58:08 → 23:53:33 across the session).
