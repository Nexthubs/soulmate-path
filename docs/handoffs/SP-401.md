## 1. Scope completed
- Implemented typed domain schemas in `backend/app/soulmate/domain/paypal_models.py` for PayPal catalog products, monthly billing cycles (`PayPalBillingCycle`), payment preferences, plan payloads (`PayPalPlanPayload`), and structured verification results (`PayPalPlanVerificationResult`).
- Implemented asynchronous PayPal REST API client in `backend/app/soulmate/services/paypal_client.py` supporting OAuth2 client credentials authentication, token caching/renewal, and REST endpoints for catalog products (`/v1/catalogs/products`) and billing plans (`/v1/billing/plans`), with sanitized error handling preventing credential leakage.
- Implemented `PayPalProvisioningService` in `backend/app/soulmate/services/paypal_provisioning.py` for repeatable creation, detection, and contract verification of reusable PayPal billing objects:
  - Canonical 2-cycle intro plan payload builder strictly matching DEV-SPEC §9.1.1 (Cycle 1: `TRIAL`, sequence 1, total_cycles 1, `MONTH` x 1, intro price; Cycle 2: `REGULAR`, sequence 2, total_cycles 0, `MONTH` x 1, regular renewal price; `auto_bill_outstanding=True`, `payment_failure_threshold=1`).
  - Canonical 1-cycle standard plan payload builder strictly matching DEV-SPEC §9.2 for `PAY-02` re-subscription policy (Cycle 1: `REGULAR`, sequence 1, total_cycles 0, `MONTH` x 1, regular price).
  - Strict monthly cadence verification enforcing `interval_unit == 'MONTH'` and `interval_count == 1`.
  - Re-run safety and idempotency: detects existing products and plans by ID or by catalog/plan specification match, preventing duplicate plan creation.
  - Programmatic disclosure matching verifying that server offer disclosures (`today_text`, `renewal_text`) match the provisioned plan amounts.
  - Generates copy-pasteable `.env` configuration snippet for provisioned Product ID and Plan IDs.
- Implemented executable CLI tool in `backend/scripts/provision_paypal.py` supporting `--dry-run` inspection, full Sandbox provisioning, and `--verify-only` plan validation, strictly enforcing Decision `PAY-01` (refusing to invent or default production prices).
- Authored comprehensive automated test suite in `backend/tests/test_paypal_provisioning.py` (14/14 tests passing).

## 7. High-risk checks when applicable
- **Authorization / ownership:** Plan templates are reusable infrastructure templates. Plans are never created per-user (Spec §9.2).
- **Idempotency / concurrency:** Provisioning inspects existing catalog products and plans; re-running reuses matching active plans rather than multiplying objects in PayPal. Concurrency safety is enforced at both process level (`asyncio.Lock` serialization) and distributed level (deterministic `PayPal-Request-Id` derived from payload parameters on POST endpoints). Verified by `test_provisioning_service_concurrency_safety` where 5 concurrent requests create exactly 1 product and 1 plan.
- **Failure / retry:** PayPal REST errors and OAuth failures are caught and surfaced via typed `PayPalAPIError` / `PayPalAuthError` without logging secrets.
- **Payment / entitlement authority:** Sets up provider billing templates only; does not grant entitlement or mark user as paid.
