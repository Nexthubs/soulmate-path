## 1. Scope completed
- **Single aggregate endpoint** `GET /api/soulmate/result` (mounted at `<api_prefix>/result`, tags `Result`):
  one response supplies `server_time`, `subscription {provider, provider_status, first_payment_at, next_billing_at}`, and `sketch`/`report` views (`unlock_at`, `availability`, `generation`, combined `status` per SP-502 §10.3 derivation) — the client merges nothing (AC 1).
- **Authorization isolation (AC 2):**
  - Authentication required: session cookie `soulmate_sid` (or `X-Soulmate-Session-Token` / Bearer fallback) or `session_id` query param validated by `verify_session_ownership`; anonymous → 403; cross-session `session_id` → 403 `FORBIDDEN_OWNERSHIP` (IDOR, DEV-SPEC §20).
  - Entitlement gate: session without `subscription_success_at` (set transactionally only with a confirmed first payment) → 403 — an ACTIVE-looking subscription without `first_payment_at` grants nothing (H-3, PAY-AUTH-01).
- **Stable schema (AC 3):** pydantic response models `ResultAggregateResponse` / `ResultSubscriptionView` in `app/soulmate/schema.py`, artifact views reuse SP-502's `ArtifactStatusView` (single source of truth); response shape is additive-friendly for polling (SP-505) and matches §10.4 plus the additive combined `status` field.
- **SP-501 self-heal on read:** if an entitled session is missing artifact placeholder rows, the aggregate triggers `SubscriptionService.ensure_artifacts_for_session` (new public delegate over the idempotent SP-501 ensure) with the authoritative `first_payment_at`, then re-derives statuses; unlock times are rebuilt from the first payment, never from the read instant.
- **TIME-01:** all statuses derive from persisted timestamps + server clock; no client time input anywhere in the path.

## 7. High-risk checks when applicable
- **Authorization / ownership:** token + ownership verification on every request; entitlement gate keyed to server-persisted `subscription_success_at`; no data leakage across sessions (IDOR test).
- **Payment / entitlement authority (`PAY-AUTH-01`):** unentitled sessions receive 403 regardless of subscription provider status; only confirmed first payment unlocks the aggregate.
- **Unlock time authority (`TIME-01`):** response exposes persisted `unlock_at` and server `server_time`; client cannot derive access from its own clock; self-heal rebuilds unlocks from `first_payment_at` only.
- **Idempotency / concurrency:** read path is stateless; self-heal reuses the SP-501 concurrency-safe create/ensure (savepoint + unique constraints).

## 8. Deviations / implementation decisions
- Response adds the combined per-artifact `status` field on top of the §10.4 fields (`unlock_at`, `availability`, `generation`) — additive extension carrying SP-502's derivation so SP-106/SP-504 don't re-derive it.
- Unentitled access returns 403 (rather than an empty/locked 200 payload): the Result page is gated server-side by route guards, so a 200-with-locked-state would only invite client-side ambiguity about entitlement.

## 9. New risks / TBDs / known limitations
- None. Self-heal on read only runs when placeholder rows are missing; normal polls add two SELECTs.
