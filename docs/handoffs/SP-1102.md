- **`globals.css`:** new reusable utilities — `--sp-safe-top`/`--sp-safe-bottom` (env safe-area custom properties, 0px on desktop) and `.sp-fill-vh` (`100vh` fallback → `100dvh` under `@supports`).

Safe-area: header `pt` = 1.5rem + `--sp-safe-top`; footer `pb` = 2.5rem + `--sp-safe-bottom`; when no footer exists the bottom safe area goes on `main`'s `pb` instead (no double-stacking).
- **`TransitionShell.tsx`:** same split; slot carries `px-6`, `pt` = 2rem + safe-top, `pb` = 2rem + safe-bottom.
- **`FlowShellFallback.tsx`:** full-width gradient + `sp-fill-vh`, matching the shells (quiz/loading/email inline Suspense fallbacks all consume it; those routes have no route-level `loading.tsx` files — nothing else to change).
- **`EmailCaptureView.tsx`:** own cool gradient extended full-width; centered 390px slot keeps all content (sketch illustration stays inside the slot); white card `pb` = 2.5rem + safe-bottom.
- **`soulmate/error.tsx`:** white 390px card replaced with the full-width warm gradient (no obvious background regression for the guard/error state).
- **Out-of-scope pages verified, zero changes needed:** landing, sketch, subscribe, result, report, settings, payment-processing already self-constrain (`max-w-[390|420px] mx-auto` + own gradients) — they render exactly as before over the body background. ## 8. Deviations / implementation decisions
- Top safe-area added to the shells' header/top padding (quiz `pt-6`, transition `pt-8` bases) because the header/badge content is edge-attached under `viewportFit: cover`; `env()` is 0 on desktop so the 390px desktop geometry is pixel-identical. Bottom safe-area is applied exactly once per shell (footer when present, otherwise the content slot; email on the white card).
- `.sp-fill-vh` is a plain-CSS utility (not Tailwind) to keep the explicit `100vh → 100dvh` fallback chain the plan requires.
- The plan's "loading.tsx" items resolved to: no route-level `loading.tsx` exists for quiz/loading/email — their Suspense fallbacks are inline `FlowShellFallback`, which was updated.
- **Follow-up fix (owner feedback, 2026-09-30):** the landing page initially kept its own 390px gradient column, exposing the body background outside it on wide screens. `SoulmateLandingPage` root received the same full-width background + centered 390px slot split (safe-area on the header top). Verified at 1440 (gradient covers viewport, 0 overflow, screenshot `batch1-landing-1440-fixed.png`) and 390 (CTA center at 195px — geometry unchanged); frontend suite 441/441.
