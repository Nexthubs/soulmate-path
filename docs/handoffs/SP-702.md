## 1. Scope completed
- **Report persistence service** ([`backend/app/soulmate/services/report_service.py`](file:///Users/zhaozhao/AI%20Coding/Soumate%20Path/backend/app/soulmate/services/report_service.py)):
  - `ReportService.save_completed_report(db, session_id, report, *, provider, model, prompt_version, provider_request_id)`:
    - validates the payload through the SP-701 contract (`parse_soulmate_report_v1`) **before** touching any row — an invalid payload (including the §13.2 content policy) causes no partial write;
    - persists the validated **camelCase** `SoulmateReportV1` dump (`schemaVersion` included) onto the session's REPORT row `content_json` (JSONB), sets `generation_status=COMPLETED`, `completed_at`, and the §13.3 provider metadata columns (`provider`/`model`/`prompt_version`/`provider_request_id`);
    - **no-clobber idempotency:** the row is selected `FOR UPDATE` so concurrent saves serialize; a row already `COMPLETED` with content is returned unchanged (`saved=False`) — the first completed V1 report is the canonical durable asset and is never overwritten (report-side application of the ASSET-01 revisit rule);
    - raises `NotFoundError` when the SP-501 placeholder row is missing (entitlement drift; row creation stays owned by SP-501's self-heal);
    - `unlock_at` is never written here — it is the SP-501-persisted `first_payment_at + 24h` and stays immutable (TIME-01).
  - `ReportService.get_report_artifact(db, session_id)`: the session's single canonical REPORT row. Strictly session-scoped (Decision RECOVERY-01) — no email-scoped fallback like the sketch row.
  - `ReportService.get_report_content(artifact)`: read-path re-validation — returns the stored camelCase payload only after it passes `parse_soulmate_report_v1` again; corrupt stored content raises `ReportValidationError` (fail closed, never silently rewritten) and unfinished rows return `None`.
- **Authorized retrieval endpoint** (`GET /api/soulmate/artifacts/report`, DEV-SPEC §15.11; [`backend/app/api/soulmate/artifacts.py`](file:///Users/zhaozhao/AI%20Coding/Soumate%20Path/backend/app/api/soulmate/artifacts.py)):
  - same auth/ownership pattern as the Result aggregate and sketch endpoints (`_resolve_authorized_session`, §20): cookie session or `session_id` query param with `verify_session_ownership` (403 on mismatch/absence);
  - responds with `ReportResponse { server_time, report (ArtifactStatusView), content }`; `content` (validated camelCase `SoulmateReportV1`) is present **only** when the combined §10.3 state is `COMPLETED` — i.e. unlocked past the persisted `report_unlock_at` AND generation finished (LOCKED/READY/GENERATING/FAILED rows carry status only);
  - path follows the established sketch implementation mount (`/artifacts/report`, pre-documented in `router.py`) rather than the spec's literal `/report` — same §15.10→`/artifacts/sketch` deviation SP-603/607 already established.
- **§13.3 provider config surface for the owner-directed OpenAI-compatible generator** ([`backend/app/core/config.py`](file:///Users/zhaozhao/AI%20Coding/Soumate%20Path/backend/app/core/config.py), [`.env.example`](file:///Users/zhaozhao/AI%20Coding/Soumate%20Path/.env.example)):

## 7. High-risk checks when applicable
- **Authorization / ownership (§20):** retrieval requires an authenticated session; `session_id` param is ownership-checked; REPORT is strictly session-scoped (RECOVERY-01) — no email fallback, tested.
- **Unlock authority (TIME-01):** unlock decision reads the persisted `unlock_at`; the service never writes unlock timestamps; a COMPLETED report before `unlock_at` is served as LOCKED without content (tested).
- **Uniqueness / concurrency (§14):** DB unique constraint is the final guard (IntegrityError test); service-level save serializes on `FOR UPDATE` and is no-clobber, so a second generation can never replace a durable report.
- **Payment/entitlement authority (PAY-AUTH-01):** no new entitlement logic; placeholder rows still come only from verified-payment paths (SP-501); missing rows fail closed.
- **Report production rule (REPORT-01/02):** `SOULMATE_REPORT_PROVIDER` default stays empty; `is_report_generation_enabled` False; no generation path added.

## 8. Deviations / implementation decisions
- Endpoint mounted at `/api/soulmate/artifacts/report` instead of §15.11's literal `GET /api/soulmate/report`, matching the established §15.10 sketch deviation (`/api/soulmate/artifacts/sketch`) and the router's own §15.11 comment.
- Content stored camelCase (renderer-contract form) rather than snake_case; `schemaVersion` rides inside `content_json` while the row's `artifact_version` column continues to track the artifact lifecycle version.
- Save commits inside the service (mirrors `SketchGenerationService`), so future worker/job contexts (SP-704) can call it outside the request lifecycle.
- Added the provider config keys in this task (rather than leaving all config to SP-704) per the owner's explicit request for env-configurable endpoint URL / API key / model; no provider code was enabled.

## 9. New risks / TBDs / known limitations
- Stored-content corruption surfaces as HTTP 400 `VALIDATION_ERROR` on the read path (fail closed). A future maintenance path could distinguish "corrupt row" (5xx) from "bad request" if needed.
- `save_completed_report` writes `provider_request_id` when given; the column is opaque and provider-agnostic.
