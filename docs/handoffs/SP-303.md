## 1. Scope completed
- **Core Domain Logic (`backend/app/soulmate/domain/offer.py`):**
  - Currency symbol formatting (`get_currency_symbol`) with fallback for non-USD.
  - Price formatting (`format_offer_price`) honoring Decision `PAY-01` (formats Decimal to 2 decimal places, or returns `{INTRO_PRICE}` / `{REGULAR_PRICE}` placeholders when unconfigured).
  - Decision `PAY-02` eligibility evaluation (`evaluate_resubscription_eligibility`):
    - First-time subscriber: `eligible_for_intro=True`, `plan_class="intro"`, `is_blocked=False`.
    - Returning subscriber: evaluated against configurable `SOULMATE_RESUBSCRIPTION_POLICY`:
      - `'blocked'` (default per PAY-02): `is_blocked=True`, `plan_class="blocked"`, `eligible_for_intro=False` with explicit reason.
      - `'single_intro'`: routes to standard pricing plan (`plan_class="standard"`, `eligible_for_intro=False`).
      - `'allow_intro'`: grants intro price again (`plan_class="intro"`, `eligible_for_intro=True`).
  - Structured renewal disclosures (`build_subscription_offer`): `today_text`, `renewal_text`, `terms_text`, `interval`, `interval_count`, `auto_renew` per DEV-SPEC §9.1 and §21.
  - Safe client integration metadata: public client ID, environment, active PayPal plan ID; zero private credentials, client secrets, or webhook IDs exposed.
- **Backend Schema & Settings (`backend/app/soulmate/schema.py`, `backend/app/core/config.py`):**
  - Added schemas: `RenewalDisclosure`, `OfferEligibility`, `PayPalClientConfig`, `SubscriptionOfferResponse`.
  - Added `soulmate_resubscription_policy` field to `Settings` defaulting to `"blocked"` and added production validation.
  - Documented `SOULMATE_RESUBSCRIPTION_POLICY` in `.env.example`.
- **Backend Service Layer (`backend/app/soulmate/services/offer_service.py`):**
  - Implemented async `OfferService` with `check_prior_subscription` verifying `Subscription` table for session ID, user ID, or matching email.
  - `get_subscription_offer` dynamically combines settings, prior subscription status, and domain rules.
- **HTTP API Endpoints (`backend/app/api/soulmate/subscription.py`, `router.py`):**
  - `GET /api/soulmate/subscription/offer` supporting optional session resolution (via cookie `soulmate_sid` or query param `session_id` with IDOR verification).
  - `GET /api/soulmate/checkout/config` alias mounted on router per DEV-SPEC §15.6 router specifications.
- **Frontend Client & UI (`frontend/src/soulmate/api/subscription.ts`, `frontend/src/app/soulmate/subscribe/page.tsx`):**
  - Exported typed interfaces and `getSubscriptionOffer(sessionId?)` API client.
  - Integrated `getSubscriptionOffer` into Subscribe page; dynamically renders today amount, renewal amount, renewal disclosures, and eligibility status without hardcoded prices.
  - Preserved existing query-parameter forwarding to `/soulmate/result` and page heading.
- **Automated Tests:**
  - Added 13 comprehensive backend unit and integration tests in `backend/tests/test_subscription_offer.py`.
  - Added frontend tests in `frontend/tests/subscription-offer.test.tsx`.

## 7. High-risk checks when applicable
- Authorization / ownership: `verify_session_ownership` prevents users from inspecting other users' sessions or subscription eligibility; IDOR returns 403.
- PAY-01 compliance: Prices are Decimal/strings injected from configuration, defaulting to placeholders if unset; zero hardcoded prices in UI or backend domain.
- PAY-02 compliance: Does not guess re-subscription promotional policy; blocks by default pending product resolution.
- Secret leakage prevention: `PayPalClientConfig` contains only public `client_id`, `env`, and `plan_id`; `client_secret` and webhook IDs are never serialized.

## 8. Deviations / implementation decisions
- **H-2 Audit Remediation (Unconditional Result Navigation Blocked):** Remediated the unentitled "Continue to Result Dashboard" link on `/soulmate/subscribe`. The button is now disabled (`🔒 Complete Payment to Access Results`) for unpaid users, preventing confusing unentitled navigation prior to PayPal payment completion (DEV-SPEC §3, §9.1). Added test coverage in `frontend/tests/subscription-offer.test.tsx` and `frontend/tests/app-pages.test.tsx`.
- **H-4 Audit Remediation (Standard Pricing Disclosure & Missing Plan ID Handling):** In `backend/app/soulmate/domain/offer.py`:
  - When returning subscriber is routed to `plan_class == "standard"` under `single_intro` policy, `today_text` is formatted using regular price (`Today: $35.00`), NOT promotional intro price.
  - If `standard_plan_id` is missing/unconfigured when standard plan is required, eligibility is blocked (`is_blocked = True`, `paypal_plan_id = None`) rather than falling back to intro plan.
  - Verified by `test_offer_service_configurable_via_settings_pay_01_pay_02` and `test_standard_plan_blocked_when_unconfigured_h4`.
- Implemented `/checkout/config` as an alias pointing to `/subscription/offer` to support both DEV-SPEC §15.6 text and router overview table without discrepancies.
- Added graceful offline/error fallback in `SubscribeContent` so testing or mock environments without backend running continue to render without crashing.
