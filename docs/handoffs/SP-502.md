## 1. Scope completed
- **Pure derivation domain module** `backend/app/soulmate/domain/artifact_status.py`:
  - `ArtifactAvailability` (LOCKED/UNLOCKED, §10.1), `ArtifactGeneration` (NOT_STARTED/QUEUED/PROCESSING/COMPLETED/FAILED, §10.2), `ArtifactStatus` (LOCKED/READY/GENERATING/COMPLETED/FAILED, §10.3 combined).
  - `derive_availability(unlock_at, now)` — LOCKED while `now < unlock_at`, UNLOCKED at the boundary (`now == unlock_at`).
  - `derive_artifact_status(unlock_at, generation_status, now)` — combined state per §10.3; LOCKED wins over any generation state; QUEUED/PROCESSING → GENERATING; unknown persisted generation values fail closed to FAILED (never READY).
  - `derive_artifact_status_view(...)` → `ArtifactStatusView` (`unlock_at`, `availability`, `generation`, `status`); missing row (unlock_at=None) fails closed to LOCKED.
  - `SessionArtifactStatuses` container carries `server_time` (the exact clock instant used) plus sketch/report views, matching the §10.4 response shape.
- **Service wrapper** `backend/app/soulmate/services/status_service.py`: `ArtifactStatusService.get_artifact_statuses(db, session_id, now=None)` loads persisted artifact rows and derives both statuses; `now` is injectable (defaults to server `utc_now()`), enabling deterministic fake-clock tests.
- **Client-clock independence (TIME-01):** derivation is a pure function of persisted timestamps + the injected server clock; no client time input exists anywhere in the derivation path.
- **Typed contracts:** pydantic models (`ArtifactStatusView`, `SessionArtifactStatuses`) follow the existing `domain/*_models.py` conventions, ready for SP-503's aggregate API response.

## 8. Deviations / implementation decisions
- Unknown/corrupt persisted `generation_status` values map to FAILED (fail-closed: Retry/Support) rather than raising — a read path must not 500 on corrupt data, and FAILED never grants content access. Recorded here as an implementation-local decision; no DEV-SPEC semantics changed (§10.2 defines the only legal states).
- Missing artifact rows fail closed to LOCKED with `unlock_at=None` instead of reconstructing unlock times from `first_payment_at` — avoids a second derivation source that could drift from the persisted authority; SP-503 can trigger the SP-501 self-heal if it encounters this state.
