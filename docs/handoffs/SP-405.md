## 1. Scope completed
- Implemented official PayPal signature verification mechanism calling `POST /v1/notifications/verify-webhook-signature` in `PayPalClient.verify_webhook_signature(...)`.
- Implemented `PayPalWebhookVerifier` service with defense-in-depth security:
  - `is_valid_paypal_cert_url`: Validates `cert_url` scheme (`https`), port (`443` or default), and strict domain origin (`paypal.com` or `*.paypal.com`) to prevent SSRF and malicious certificate injection.
  - Transmission headers completeness validation: ensures all 5 required transmission headers (`PAYPAL-AUTH-ALGO`, `PAYPAL-CERT-URL`, `PAYPAL-TRANSMISSION-ID`, `PAYPAL-TRANSMISSION-SIG`, `PAYPAL-TRANSMISSION-TIME`) are present before calling external services.
  - Webhook ID configuration validation: fails safely if `PAYPAL_WEBHOOK_ID` is unconfigured.
  - Safe error logging: logs event ID, transmission ID, and error codes without leaking API secrets, bearer tokens, or PII.
- Integrated `PayPalWebhookVerifier` dependency into `backend/app/api/soulmate/webhooks.py` using FastAPI `Depends(get_webhook_verifier)`.
- Enforced High-Risk Invariant `PAY-AUTH-01`: unverified or forged webhooks are rejected with HTTP 400 `WebhookVerificationError` without writing to `paypal_webhook_events` or mutating `Subscription`, `SubscriptionPayment`, `SoulmateSession`, or `SoulmateArtifact`.
- Created comprehensive test suite in `backend/tests/test_paypal_webhook_verifier.py` (29 tests) and updated `backend/tests/test_paypal_webhooks.py` (15 tests).

## 7. High-Risk checks when applicable
- **Authorization / ownership:** Webhook endpoint is publicly accessible to PayPal without user auth tokens, but cryptographic verification ensures only authentic PayPal servers can trigger events.
- **Idempotency / concurrency:** Handled via unique `paypal_event_id` constraint and duplicate return logic (verified in SP-404, preserved in SP-405).
- **Failure / retry:** Permanent verification errors return 400 Bad Request to halt retry loops. Transient network errors return False safely.
- **Payment / entitlement authority (PAY-AUTH-01):** Verified that unverified or forged webhooks targeting an existing session NEVER update `subscription_success_at`, create `Subscription` records, create `SubscriptionPayment` records, or store unverified events as successful.

## 8. Deviations / implementation decisions
- Implemented defense-in-depth URL origin validation (`is_valid_paypal_cert_url`) checking HTTPS scheme, trusted domain (`paypal.com` or `*.paypal.com`), and standard port (443 or default) before making any outbound calls to verify signatures. This prevents SSRF or certificate confusion attacks.

## 9. New risks / TBDs / known limitations
- Webhook events in local development without network access or sandbox credentials require mock verifier override (`get_webhook_verifier`).
- `PAYPAL_WEBHOOK_ID` must be configured in production/sandbox `.env` once registered on PayPal Developer Dashboard.
