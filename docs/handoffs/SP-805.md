## 1. Scope completed
- **New pure helper `derivePaidAccessCopy`** (exported from `SubscriptionSettingsAction.tsx`): derives the access-status headline and explanatory detail from the actual reconciled state and dates. State → copy mapping:
  - `CANCELLED` / `EXPIRED` with a **future** paid-through date → "Active through {date}" + "You retain full access to all paid features through {date}." (the paid cycle per §9.8 is still running);
  - `CANCELLED` / `EXPIRED` with a **past** paid-through date → "Paid access ended {date}" + "Your paid access period has ended." — the previous hard-coded "Active through" claim is no longer made for expired windows;
  - `CANCELLED` without dates → "Access retained" + "No future renewal charges will be made." (truthful, no access-window claim);
  - `SUSPENDED` → "Suspended" + suspension copy with **no renewal promise** (previously fell into the generic auto-renew sentence — an unsupported renewal promise);
  - `EXPIRED` without dates → "Expired" + "No future renewal charges will be made.";
  - unpaid `PROCESSING` → confirmation copy ("paid access begins only after your first payment is confirmed") grounded in PAY-AUTH-01 (previously also showed the auto-renew sentence prematurely);
  - `ACTIVE` paid → unchanged supported auto-renew copy (§9.1 V1 monthly plan).
- **Date fallback per §9.8:** `paid_through_at`, falling back to `next_billing_at` (the saved next billing time marks the end of the already-paid cycle) — matching the SP-409 cancellation flow that persists PayPal's `next_billing_time` as `paid_through_at`.
- **No-refund/renewal promises:** the only renewal promise remaining is the ACTIVE auto-renew sentence (supported by §9.1 + user-cancellable per §9.8); no refund promises anywhere; the SP-804 dialog's "no refund for the current cycle" statement is unchanged.
- Component wiring: the cancelled card (`paid-through-display` / new `paid-access-detail` testids) and the non-cancelled detail paragraph render the derived copy; the "Next Renewal Date" row now renders only for the auto-renewing (ACTIVE paid) state, so suspended/processing sessions no longer see a renewal date claim.
- The artifact-retention guarantee ("never be deleted") is unchanged and renders in every cancelled/ended state (§9.8 + ASSET-01).

## 8. Deviations / implementation decisions

If the owner prefers server-tense-only, the status response would need a `server_time` field — flagged as a possible M6 refinement, not done here to keep the additive-contract surface unchanged.
- EXPIRED and CANCELLED share the same ended/active/retained copy branches (both mean "no future renewal"); only the badge distinguishes them (existing behavior).
