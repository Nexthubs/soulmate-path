## 1. Scope completed

- Implemented server-side PayPal subscription cancellation (`POST /v1/billing/subscriptions/{id}/cancel`) via `SubscriptionService.cancel_subscription` and `PayPalClient.cancel_subscription`.
- Implemented preservation of paid access: fetches latest `billing_info.next_billing_time` from PayPal before calling cancellation and persists as local `paid_through_at` (DEV-SPEC §9.8, §15.9).
- Handled idempotency and repeated cancellations safely: returns 200 `CANCELLED` response without repeating provider calls or raising error. Also handles PayPal HTTP 422 `SUBSCRIPTION_STATUS_INVALID` gracefully.
- Enforced high-risk invariant: previously generated and unlocked artifacts (`SoulmateArtifact`) are permanently retained and never deleted upon cancellation (DEV-SPEC §9.8, §10, ASSET-01).
- Implemented and mounted canonical REST endpoints and router aliases:
  - `POST /api/soulmate/subscription/cancel` (primary route)
  - `POST /api/account/subscription/cancel` (DEV-SPEC §15.9 canonical alias mounted on FastAPI app)
  - `POST /api/soulmate/subscriptions/cancel` (DEV-SPEC §15 router table alias)
- Implemented session ownership authentication and IDOR prevention (`verify_session_ownership`).
- Enhanced webhook handler `BILLING.SUBSCRIPTION.CANCELLED` to also preserve `paid_through_at` and clear `next_billing_at`.
- Updated frontend subscription client: added `cancelSubscription` API call with types `SubscriptionCancelPayload` and `SubscriptionCancelResponse`, and added `paid_through_at` and `cancelled_at` to `SubscriptionStatusResponse`.
- Built frontend Settings Action UI component: `frontend/src/soulmate/components/settings/SubscriptionSettingsAction.tsx` handling active state, confirmation dialog, post-cancel paid-through access display, and artifact retention guarantee.
- Added comprehensive backend tests (7 unit/integration tests in `backend/tests/test_subscription_cancellation.py`) and frontend tests (5 tests in `frontend/tests/subscription-cancellation.test.tsx`).

## 7. High-risk checks when applicable

- **Authorization / ownership:** Strict IDOR enforcement. Session public ID must match authenticated token; unauthorized sessions return HTTP 403 `FORBIDDEN_OWNERSHIP`.
- **Idempotency:** Re-cancelling returns existing `CANCELLED` status without re-calling PayPal or modifying state.
- **Entitlement / Access:** Entitlement continues until `paid_through_at` (derived from PayPal's authoritative `next_billing_time`). Already generated sketches/reports remain permanently accessible.
- **Data integrity:** Zero cascade deletions on cancellation.

---

## 8. Deviations / implementation decisions

- DEV-SPEC §9.8 specifies saving `billing_info.next_billing_time` as `paid_through_at` before invoking PayPal cancel. In addition, if PayPal does not return a future billing time (e.g. trial or already cancelled), fallback logic derives `paid_through_at` from existing `next_billing_at` or `first_payment_at + 30 days` to guarantee non-null paid access period for active subscribers.
- Supported both `/api/soulmate/subscription/cancel` and `/api/account/subscription/cancel` to ensure full compatibility with DEV-SPEC §15.9 and the frontend API client.
