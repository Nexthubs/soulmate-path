## 1. Scope completed
- **Authoritative Provider State Reconciliation:**
  - Implemented `SubscriptionService.reconcile_subscription` to query PayPal Subscriptions v1 REST API (`GET /v1/billing/subscriptions/{id}`) as an independent authority source alongside webhooks.
  - Implemented session-level reconciliation via `SubscriptionService.reconcile_session_subscription` and exposed endpoint `POST /api/soulmate/subscription/reconcile`.
  - Added optional live reconciliation fallback (`?reconcile=true`) to `GET /api/soulmate/subscription/status` to eliminate frontend polling deadlocks when webhooks are delayed or dropped.
- **Authoritative First Payment Invariant (`PAY-AUTH-01`, `TIME-01`):**
  - When confirmed by PayPal's `billing_info.last_payment`:
    - `Subscription.first_payment_at` is set to the authoritative payment UTC timestamp exactly once;
    - `SoulmateSession.subscription_success_at` is set and status transitions to `paid` (`current_step = "result"`);
    - Durable artifact rows (SKETCH +12h, REPORT +24h) are created idempotently via `_ensure_artifacts_initialized`;
    - Ledger payment is recorded via `PaymentLedgerService.record_payment`.
  - Once established, `first_payment_at` and `subscription_success_at` are immutable against subsequent renewals, delayed events, or repeat reconciliations.
- **Deterministic State Mapping & Monotonicity:**
  - `APPROVAL_PENDING` / `APPROVED` -> `PROCESSING` (`is_paid = False`).
  - `ACTIVE` -> `ACTIVE` (`is_paid = True` if `first_payment_at` is confirmed; otherwise `PROCESSING`).
  - `SUSPENDED` -> `SUSPENDED` (`is_paid = True` if previously paid, artifacts retained).
  - `CANCELLED` -> `CANCELLED` (`is_paid = True` if previously paid, access retained until `paid_through_at`).
  - `EXPIRED` -> `EXPIRED` (`is_paid = True` if previously paid, artifacts retained).
  - Enforced terminal state monotonicity: local `CANCELLED` and `EXPIRED` states can never be regressed to `ACTIVE` or `APPROVAL_PENDING` by PayPal API responses.
- **Artifact Preservation on Cancellation:**
  - Cancellation or expiration transitions `provider_status` and records `cancelled_at` / `expired_at`, but **never** deletes or nullifies rows in `soulmate_artifacts`. Already-generated or in-progress artifacts remain permanently accessible.
- **Billing Dates Synchronization:**
  - Reconciles `next_billing_at` and `paid_through_at` from `billing_info.next_billing_time`.

- **Artifact retention:** Cancellation never deletes generated artifacts.
