## 1. Scope completed
- **Dedicated Payment Ledger Domain & Service:**
  - Implemented `PaymentLedgerService` (`backend/app/soulmate/services/ledger_service.py`) as the single source of truth for payment ledger mutations, idempotency deduplication, and customer reconciliation queries.
  - Implemented typed DTOs and models in `backend/app/soulmate/domain/ledger_models.py` (`PaymentRecordCreate`, `PaymentLedgerRecord`, `PaymentLedgerSummary`, `LedgerSearchQuery`, `LedgerSearchResult`).
- **Durable Payment Record Storage & Cycle Derivation:**
  - Each completed provider payment record persists:
    - `provider_payment_id`: durable PayPal Sale/Capture ID (unique constraint enforced);
    - `amount`: Decimal monetary value;
    - `currency`: ISO-4217 3-letter currency code;
    - `paid_at`: authoritative UTC timestamp from PayPal;
    - `subscription_id`: relational foreign key link to `subscriptions.id`;
    - `cycle_no`: billing cycle context (1 for intro month, 2+ for recurring cycles);
    - `raw_json`: complete raw provider resource payload.
- **Provider Payment ID Idempotency:**
  - Enforced deduplication at both the database level (`UNIQUE` on `provider_payment_id`) and service level (`PaymentLedgerService.record_payment` checks existence and returns existing record with `created=False`).
  - Repeat webhook events or concurrent deliveries never create duplicate rows in `subscription_payments`.
- **Refund & Reversal Tracking:**
  - Implemented `record_refund` to update ledger record status to `REFUNDED` or `REVERSED` with `refunded_at` and audit metadata.
- **Customer Support & Reconciliation Lookups:**
  - Implemented rich lookup functions on `PaymentLedgerService`:
    - `get_payment_by_provider_payment_id`: direct lookup by PayPal capture/sale ID with contextual hydration (`provider_subscription_id`, `session_public_id`, `customer_email`);
    - `get_payments_by_subscription_id`: ordered billing cycle history;
    - `get_payments_by_provider_subscription_id`: lookup by PayPal subscription ID (`I-...`);
    - `get_payments_by_session_public_id`: lookup by session public ID;
    - `get_payments_by_email`: lookup by customer normalized email;
    - `search_payments`: multi-criteria filtering with pagination (`limit`, `offset`), status, and date range;
    - `get_subscription_ledger_summary`: aggregate statistics (completed count, total amount paid, cycles, latest status).
- **API Endpoints:**
  - Mounted customer support / reconciliation endpoints under `/api/soulmate/ledger`:
    - `GET /api/soulmate/ledger/payments/{provider_payment_id}`
    - `GET /api/soulmate/ledger/subscriptions/{provider_subscription_id}`
    - `GET /api/soulmate/ledger/summary/{subscription_id}`
    - `GET /api/soulmate/ledger/search`
  - Added user-facing session payment history endpoint:
    - `GET /api/soulmate/subscription/payments` (protected against IDOR via session ownership validation).
- **Service Integration:**
  - Integrated `PaymentLedgerService` into `PayPalWebhookService` (`_handle_payment_sale_completed`, `_handle_payment_failed`, `_handle_payment_refunded`).
