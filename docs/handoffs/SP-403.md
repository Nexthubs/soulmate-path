## 1. Scope completed
- **PayPal Client Subscriptions Endpoint (`backend/app/soulmate/services/paypal_client.py`):**
  - Added `get_subscription(subscription_id)` to query `GET /v1/billing/subscriptions/{id}` from PayPal REST API.
  - Added `cancel_subscription(subscription_id, reason)` to query `POST /v1/billing/subscriptions/{id}/cancel`.
- **Subscription Domain Schemas (`backend/app/soulmate/schema.py`):**
  - Added `PayPalConfirmRequest`, `PayPalConfirmResponse`, and `SubscriptionStatusResponse`.
- **Subscription Service (`backend/app/soulmate/services/subscription_service.py`):**
  - Implemented `confirm_paypal_subscription`:
    - Server-side format and provider validation via PayPal REST API.
    - Plan validation ensuring `plan_id` matches active Soulmate plans (`paypal_soulmate_intro_plan_id` or `paypal_soulmate_standard_plan_id`).
    - Status validation rejecting terminal states (`CANCELLED`, `EXPIRED`, `SUSPENDED`).
    - Session ownership & IDOR protection: Rejects cross-session subscription hijacking with `ForbiddenOwnershipError`.
    - Idempotency: Re-submitting the same subscription ID for the same session returns the existing record without creating duplicate rows.
    - **High-Risk Invariant (`PAY-AUTH-01`):** `first_payment_at` strictly remains `None`; `is_paid` remains `False`; status is `"PROCESSING"`.
  - Implemented `get_subscription_status`:
    - Queries latest session subscription from DB; returns `"PROCESSING"` (or provider status) when pending, or `"ACTIVE"` and `is_paid=True` once `first_payment_at` is reconciled.
- **API Endpoints & Aliases (`backend/app/api/soulmate/subscription.py`, `router.py`):**
  - `POST /api/soulmate/subscription/paypal/confirm`
  - `GET /api/soulmate/subscription/status`
  - Router aliases mounted per DEV-SPEC §9.3, §15.7, §15.8:
    - `POST /api/soulmate/paypal/confirm`
    - `POST /api/soulmate/payments/paypal/confirm`
    - `GET /api/soulmate/subscriptions/me`
- **Frontend Integration (`frontend/src/app/soulmate/payment-processing/page.tsx`, `api/subscription.ts`):**
  - Exported `confirmPayPalSubscription` and `getSubscriptionStatus` API client methods.
  - Connected `/soulmate/payment-processing` to call confirm API on mount and poll status every 2.5s up to 60s timeout (DEV-SPEC §15.8).
  - Automatically redirects to `/soulmate/result` once server status confirms `is_paid === true`.
- **Configuration & Environment:**
  - Prepared `.env` from `.env.example` ready for user-supplied `PAYPAL_CLIENT_ID` and `PAYPAL_CLIENT_SECRET`.
  - Added Pydantic field validator in `Settings` to coerce empty string price variables cleanly to `None`.
- **Automated Tests:**
  - 10 comprehensive tests in `backend/tests/test_subscription_confirm.py` covering validation, IDOR, idempotency, PAY-AUTH-01, status polling, and router aliases.
