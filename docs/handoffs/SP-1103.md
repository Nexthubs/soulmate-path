## 1. Scope completed
- **`OptionCard.tsx`:** new `locked` prop separating "interaction lock" from "genuinely disabled":
  - `locked` blocks pointer (`onClick` undefined), keyboard (`Enter`/`Space` early return), and duplicate handler calls, while keeping the card focusable (`tabIndex=0`), announcing `aria-disabled="true"`, and rendering **zero** disabled styling — selected border/checkmark and unselected states stay exactly as at rest.
  - `disabled` keeps its previous semantics and styling (dimmed, unfocusable, `pointer-events-none`) for truly unavailable options.
- **`quiz/page.tsx`:**
  - Single- and multi-choice options pass `locked={isSubmitting || isBackPending}` instead of the old greying `disabled`; the page-level handler guards (pointer + logic) remain as a second lock layer.
  - Local submitting hint: a small fixed, non-blocking "Saving…" chip (`data-testid="quiz-submit-hint"`, `aria-live="polite"`, bottom-center above safe-area) appears only after ~400ms of an in-flight submission. The timer gates **only the hint's appearance** — step advance stays server-driven; the timer is cleared on success (`advanceToNextStep`), on failure (each catch), and on unmount.
  - 150ms selection feedback and server-authoritative `next_step` routing unchanged; date/multi submit behavior (button spinner + disabled) unchanged.
- **`loading/page.tsx`:** `handleContinue` gained an explicit `if (isLoading) return;` in-handler double-submit guard (button-level `disabled`/loading state already existed).
- Failure path semantics re-verified end-to-end: selection retained, lock released, in-place error + Retry (existing mechanism), retry via the same server API.

## 8. Deviations / implementation decisions
- The submitting hint is a fixed-position chip rather than an inline row — avoids any 390px geometry change (batch-1 invariant) and cannot displace the option list; `pointer-events-none` keeps it non-blocking.
- `isBackPending` locks options via `locked` (visuals preserved) rather than `disabled` — back-pending is a transient interaction lock, not unavailability; the back button itself stays `disabled` (existing behavior).
- The eslint disable comment for the unmount-cleanup effect was dropped (rule not registered in this ESLint setup); the effect body only touches refs/state setters.

## 9. New risks / TBDs / known limitations
- Keyboard-driven double-activation was code-locked (handler guard + `locked` early return) and pointer double-tap was network-verified; exhaustive keyboard rapid-fire automation was not scripted (desktop-only environment) — low risk given the shared in-handler guard.
- The 400ms hint threshold is constant (per plan); if product later wants it configurable, gate it through config rather than hard-coding another value.
