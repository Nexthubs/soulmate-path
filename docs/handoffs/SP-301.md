## 1. Scope completed
- **Email Validation & Normalization Domain Rules** (`backend/app/soulmate/domain/identity.py`):
  - Implemented `validate_and_normalize_email(email_input)` adhering to RFC 5322 regex and RFC 5321 length limits (max 320 total, 64 local, 255 domain).
  - Normalizes email to trimmed lowercase (`email_normalized`) ensuring uniform identity representation for downstream one-email-one-sketch logic.
  - Implemented `derive_user_id_for_email(email_normalized)` providing deterministic RFC 4122 UUIDv5 identity derivation without inventing an unneeded password or separate authentication system.
- **Identity & Email Service Layer** (`backend/app/soulmate/services/identity_service.py`):
  - Implemented `IdentityService.capture_and_bind_email(db, session, email_input)`.
  - Binds anonymous sessions to existing user identity (reusing `user_id` from prior sessions sharing the same `email_normalized`) or derives a stable canonical `user_id`.
  - Atomically updates `session.email`, `session.email_normalized`, and `session.email_captured_at`.
  - Idempotently advances session status to `EMAIL_CAPTURED` and step to `subscribe` if currently on `email`.
  - Strictly preserves caller session ownership; never merges, overwrites, or exposes other user sessions.
  - Enforces DEV-SPEC §18.2 & §20 PII protection: raw email is excluded from analytics logs; structured events record only non-PII identifiers (`session_id`, `user_id`, `status`).
- **Email Capture API Endpoint** (`backend/app/api/soulmate/sessions.py`):
  - Implemented `POST /api/soulmate/sessions/{public_id}/email` returning `{ "ok": true, "next": "/soulmate/subscribe" }` per DEV-SPEC §8.2 & §15.5.
  - Guarded with `verify_session_ownership` (IDOR guard) ensuring users cannot capture or bind emails on other sessions by ID (403 `FORBIDDEN_OWNERSHIP`).
- **Frontend API Client & Integration** (`frontend/src/soulmate/api/session.ts`, `frontend/src/app/soulmate/email/page.tsx`):
  - Added typed client method `saveSessionEmail(sessionId, email)` forwarding HttpOnly credentials.
  - Connected `SoulmateEmailPage` to load active session, prefill existing email, and submit to live `POST /sessions/{id}/email` endpoint before routing to `/soulmate/subscribe`.
- **Automated Tests**:
  - `backend/tests/test_identity.py`: 12 automated unit and integration tests covering normalization, deterministic derivation, session identity binding, multiple-session identity consistency, prior session `user_id` reuse, idempotency, IDOR cross-session attack rejection, unauthenticated rejection, tampered signatures, format validation, and 404 for ghost sessions.
  - `frontend/tests/session-api.test.ts`: Added tests for `saveSessionEmail` verifying endpoint routing, credentials forwarding, and 403 error parsing.

## 7. High-risk checks when applicable
- **Authorization / ownership (DEV-SPEC §20):** Session ownership verified server-side with `verify_session_ownership`. Malicious cross-session attempts reject with HTTP 403.
- **Identity & Security (DEV-SPEC §8.3):** Submitting an email does NOT grant access to prior sessions or accounts. Session ownership remains anchored strictly to the HMAC-signed token.
- **Privacy & PII (DEV-SPEC §18.2, §20):** Raw email is excluded from analytics logging; only internal UUIDs and IDs are emitted.
- **Idempotency:** Re-submitting the same email or updating email within the session is fully idempotent.

## 8. Deviations / implementation decisions
- Implemented deterministic UUIDv5 derivation (`uuid.uuid5(uuid.NAMESPACE_URL, f"mailto:{email_normalized}")`) as fallback when no existing session with that email possesses an assigned `user_id`. This guarantees identity consistency across anonymous sessions without requiring a password/auth system.
