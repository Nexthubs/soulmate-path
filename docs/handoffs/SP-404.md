## 1. Scope completed
- Implemented unauthenticated public PayPal webhook receiver endpoint at `POST /api/webhooks/paypal` (and alias `POST /api/soulmate/webhooks/paypal`).
- Preserved incoming request body byte-for-byte in `PayPalWebhookRawRequest.raw_body` to enable cryptographic signature verification in SP-405 without framework serializer mutations.
- Case-insensitively extracted and preserved all 5 PayPal transmission headers (`PAYPAL-AUTH-ALGO`, `PAYPAL-CERT-URL`, `PAYPAL-TRANSMISSION-ID`, `PAYPAL-TRANSMISSION-SIG`, `PAYPAL-TRANSMISSION-TIME`).
- Enforced High-Risk Invariant `PAY-AUTH-01`: Unverified events NEVER mutate business state (`Subscription`, `SubscriptionPayment`, `SoulmateSession`, `SoulmateArtifact`). Missing headers or verification failure immediately rejects with HTTP 400 (`WebhookVerificationError`) and leaves business tables untouched.
- Implemented PayPal retry semantics:
  - Returns `200 OK` on verified event ingestion and on replayed duplicate delivery (`status: duplicate`, `duplicate: True`), causing PayPal to mark delivery complete and halt retries.
  - Returns `400 Bad Request` on malformed JSON, empty payload, or missing headers/event IDs (permanent client error, avoiding fruitless retry loops).
  - Returns `500 Internal Server Error` on unexpected operational failures, signaling to PayPal to retry delivery according to its exponential backoff schedule.
- Added comprehensive unit and integration tests in `backend/tests/test_paypal_webhooks.py` (15/15 passed).

## 7. High-risk checks when applicable
- **Authorization / ownership:** N/A for public webhook; explicitly exempt from user auth so PayPal servers can deliver notifications.
- **Idempotency / concurrency:** Handled via unique constraint on `paypal_webhook_events.paypal_event_id`; duplicate deliveries return 200 OK without re-running business logic.
- **Failure / retry:** Permanent errors return 400 (halts retries); unexpected errors return 500 (triggers PayPal retry).
- **Payment / entitlement authority:** Invariant `PAY-AUTH-01` verified; unverified events cannot alter subscription or entitlement state.
