## 1. Scope completed
- **App-owned provider interface** (`backend/app/soulmate/domain/sketch_models.py`):
  - `SketchImageProvider` — runtime-checkable Protocol: `provider_name` + `async generate_image(prompt) -> SketchGenerationResult`. The generation pipeline (SP-603) programs against this contract; OpenAI is swappable (verified by a fake-provider conformance test).
  - `SketchGenerationResult` — frozen pydantic model carrying **image bytes** (not provider URLs, per ASSET-01) plus §11.3/§25 tracing metadata: `provider`, `model`, `image_format`, `size`, `quality`, `provider_request_id`, `provider_created_at`, `generated_at` (server UTC), `duration_ms`, and `source_url` (tracing-only, set only on the defensive URL fallback).
  - `SketchProviderError(SoulmateAppError)` — provider failures already mapped to domain categories: `retryable=True` → `PROVIDER_UNAVAILABLE` (HTTP 503); `retryable=False` → `GENERATION_FAILED` (HTTP 502). These map onto the DEV-SPEC §11.6 job states `FAILED_RETRYABLE` / `FAILED_PERMANENT` that SP-603/604 consume. Carries safe tracing fields `provider_code` / `provider_request_id`.
  - `is_retryable_provider_status()` / `provider_code_for_status()` — shared classification and code vocabulary.
- **OpenAI adapter** (`backend/app/soulmate/services/openai_image_provider.py`):
  - `OpenAIImageProvider` — async httpx adapter for `POST https://api.openai.com/v1/images/generations` (§25), mirroring the established `PayPalClient` structure (injected `http_client` for tests, `close()`, async context manager). No new dependency added (no OpenAI SDK).
  - Request parameters from §22 configuration: `SOULMATE_IMAGE_MODEL` (default `gpt-image-2` — the spec target), `SOULMATE_IMAGE_SIZE` (`1024x1536`), `SOULMATE_IMAGE_QUALITY` (`medium`), `SOULMATE_IMAGE_FORMAT` (`webp`); constructor overrides exist for tests only. `n=1`.
  - Error mapping (tested parametrized): 429/5xx → retryable; 400/401/403/404/422 → permanent; `httpx.TimeoutException` → retryable `TIMEOUT`; `httpx.TransportError` → retryable `NETWORK_ERROR`. OpenAI body `error.type`/`error.code` (e.g. `content_policy_violation`) captured into error details; raw body kept in `internal_error` (server-log-only field, never serialized to clients by `to_client_dict`).
  - Missing `OPENAI_API_KEY` or empty prompt → fail-fast permanent error **before** any HTTP call.
  - Response handling: `data[0].b64_json` is decoded with strict base64 validation (gpt-image standard path); a `url` fallback is downloaded to bytes immediately (ASSET-01: temporary URLs are never durable storage; URL retained for tracing only); malformed/empty responses → permanent errors.
  - Tracing metadata captured safely: `x-request-id` response header → `provider_request_id`; `created` → UTC `provider_created_at`; monotonic-clock `duration_ms`. The API key exists only inside the module scope for the Authorization header — never logged, never in error messages/details, never in result payloads.
- **Shared error vocabulary** (`backend/app/core/errors.py`): extended `OpenAIErrorCode` with `FORBIDDEN="403"`, `RESOURCE_NOT_FOUND="404"`, `UNPROCESSABLE_REQUEST="422"` so every permanent HTTP category has a named code (SP-005 taxonomy extended, not weakened).
- **Exports:** `domain/__init__.py` (interface/result/errors/classifiers) and `services/__init__.py` (`OpenAIImageProvider`).

## 7. High-risk checks when applicable
- **Secrets hygiene:** Authorization header built only inside `generate_image`; logging statements receive status/type/code/request-id only; error `details`/`message` are key-free (asserted). `internal_error` may contain provider response bodies — it is a server-log-only field excluded from `to_client_dict` (SP-005 handler contract).
- **Asset durability (ASSET-01):** the interface returns bytes, not URLs; the only URL path downloads bytes immediately and flags `source_url` as tracing-only.
- **Authorization/idempotency/payment:** N/A — no endpoints, no writes, no payment logic. Idempotent re-generation is an SP-603/604 concern.
- **Failure-path correctness:** every non-200/timeout/transport/malformed path raises a categorized `SketchProviderError`; no silent None returns on failure paths.

## 8. Deviations / implementation decisions
- **No OpenAI SDK:** `requirements.txt` has no `openai` package; followed the repo's `PayPalClient` precedent (direct httpx), keeping dependencies unchanged. The §25-documented request/response shape is encoded in the adapter and locked by tests.
- **Interface takes the rendered prompt string** rather than `RenderedSketchPrompt`: keeps the provider contract media-agnostic; SP-601 metadata stays a caller concern for §11.3 persistence.
- **URL-fallback download** is defensive (gpt-image models return `b64_json`); download failures classify as retryable.
- **`OpenAIErrorCode` extension** (403/404/422) touches the SP-005 shared file — additive only, no existing member changed.

## 9. New risks / TBDs / known limitations
- Live provider behavior (actual latency, header names like `x-request-id`, `created` semantics) is asserted only against the §25-documented shape via mocks; the M4 milestone gate must validate against the real API once credentials exist.
- The adapter retries nothing itself — by design; retry/backoff belongs to the job layer (SP-604). Callers must consult `SketchProviderError.retryable`.
